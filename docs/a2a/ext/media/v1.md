# Media extension v1

**URI:** `https://madarauchiha-314.github.io/tiny-harness/a2a/ext/media/v1`

The media extension lets a client send images and audio to the agent and receive images
and spoken replies. The agent card declares it only when the agent's configuration file
has a `[media]` section. Without `[media]` the card does not change and the agent refuses
every file part.

Media bytes do not travel in A2A events. The client sends a file once, in a `raw` file
part. The server stores it and replaces the part with a `url` file part. Every later
event carries that URL, and any participant of the task reads the bytes from the media
route.

## Card params

The card lists the media types the agent accepts in `defaultInputModes` and the media
types it produces in `defaultOutputModes`. The extension's `params` repeat these types
and add the limits and the services:

```json
{
  "uri": "https://madarauchiha-314.github.io/tiny-harness/a2a/ext/media/v1",
  "required": false,
  "params": {
    "input": ["image/png", "image/jpeg", "image/webp", "image/gif", "audio/wav", "audio/webm"],
    "output": ["image/png", "audio/L16;rate=24000;channels=1"],
    "maxFileBytes": 20971520,
    "maxMessageBytes": 26214400,
    "maxAudioSeconds": 120,
    "speechToText": true,
    "textToSpeech": true,
    "imageGeneration": true,
    "mediaPath": "/media"
  }
}
```

| Param | Meaning |
|-------|---------|
| `input` | The media types the agent accepts in a file part. Images are always accepted. Audio types are accepted only when the agent can transcribe them or its model takes them. |
| `output` | `image/png` when the agent can generate images. `audio/L16;rate=24000;channels=1` when it speaks replies. |
| `maxFileBytes` | The largest file part, in bytes. |
| `maxMessageBytes` | The largest total of the file parts of one message, in bytes. |
| `maxAudioSeconds` | The longest audio file, in seconds. |
| `speechToText` | `true` when the agent transcribes audio. |
| `textToSpeech` | `true` when the agent speaks replies to a message with `speak: true`. |
| `imageGeneration` | `true` when the agent has the `generate_image` tool. |
| `mediaPath` | The path of the media route, relative to the agent's URL. |

A client uses these params to show or hide its attach, microphone and speaker controls,
and to check a file before it sends it.

## Sending media

Send each file as a `raw` file part of a `SendMessage` request, with its `mediaType` and
`filename`. The server checks every file part before the message enters the task:

1. A `url` file part is refused (`url_not_accepted`). The server never fetches a URL.
2. The `mediaType`, without parameters, must be in `input` (`type_not_accepted`).
3. Each file must be at most `maxFileBytes` (`too_large`). All files together must be at
   most `maxMessageBytes` (`message_too_large`).
4. The bytes must match the declared type (`type_mismatch`).
5. An image header must declare at most the configured pixel count
   (`image_too_large`).
6. An audio file must hold only audio (`not_audio_only`), of a duration the server can
   count (`audio_duration_unknown`), of at most `maxAudioSeconds` (`audio_too_long`).

When one check fails, the server stores nothing and starts or changes no task. The
request fails with the A2A `InvalidParams` error. The error's data holds `reason` (one
of the codes above), `limit` (when a limit applies) and `part` (the index of the refused
part). An agent without `[media]` refuses a file part with the reason `media_off`.

Only a new message may carry files. A control (complete, cancel) with a file part fails
with `InvalidParams` and the reason `files_not_accepted`.

## Metadata

The keys are plain keys of the part's or the message's `metadata`.

A file part's metadata:

| Key | Set by | Meaning |
|-----|--------|---------|
| `voice` | client | `true` for a recording made with a voice control. Clients show its transcript. |
| `durationMs` | client, server | The audio duration, in milliseconds. |
| `mediaId` | server | The id of the stored file. |
| `size` | server | The size of the stored file, in bytes. |
| `width`, `height` | server | The image size, in pixels. |

A message's metadata:

| Key | Meaning |
|-----|---------|
| `speak` | The client's speaker setting when it sent the message. `true` asks the agent to speak its reply. |

After intake, the stored message holds a `url` file part for each file. The URL is
`<agent URL>/media/<taskId>/<mediaId>`. The part keeps its `mediaType`, `filename` and
metadata, and the server adds `mediaId` and `size`.

## Events

The agent sends these A2A events for media:

| Event | Shape |
|-------|-------|
| user media | The user's message as stored: text and `url` file parts. |
| transcript | `TaskArtifactUpdateEvent` with the artifact `transcript:<mediaId>`: one text part, metadata `mediaId`. |
| agent image | `TaskArtifactUpdateEvent` with the artifact `image:<mediaId>`: one `url` file part, the name is the alt text. |
| spoken reply | `TaskArtifactUpdateEvent` with the artifact `speech:<mediaId>`: one `url` file part of type `audio/L16;rate=24000;channels=1`. |

The speech artifact comes before the reply's final status, so a client that reads the
`SendMessage` stream gets it before that stream ends.

## The media route

`GET <agent URL>/media/<taskId>/<mediaId>` returns the bytes of one stored file.

- Send the same participant identity as for the A2A requests (the `X-Participant-Id`
  header, or what the host application authenticates).
- The participant must be on the task. Otherwise the route returns `404`, also for an
  unknown id, an id of another task and a malformed id. A `404` does not confirm that
  an id exists.
- The response has `Content-Type` set to the stored type, `X-Content-Type-Options:
  nosniff`, `Content-Disposition: inline` with a sanitised file name, and
  `Content-Security-Policy: default-src 'none'`.
- A finished file has `Cache-Control: private, max-age=3600`.

## Spoken replies

A spoken reply is raw PCM: signed 16-bit little-endian samples, 24 000 samples per
second, one channel. The server writes it while the model's text is spoken, and the
media route streams it while it grows (`Cache-Control: no-store`, chunked).

- **Done.** The stream ends cleanly after the last sample.
- **Failed.** The speech service failed. The server closes the connection before the
  body is complete. The client sees a broken stream, not a clean end. The agent also
  sends a status note "speech unavailable". The text reply is not affected.
- **Interrupted.** A retry started a new attempt, or no audio arrived for 30 seconds.
  The server closes the connection before the body is complete.

To replay a reply, request the URL again. The route then sends the newest attempt from
its start. A client that does not know the extension still gets the artifact and its
URL, and can download the audio when it is done.
