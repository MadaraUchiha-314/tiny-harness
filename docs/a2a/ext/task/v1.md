# Task extension v1

**URI:** `https://madarauchiha-314.github.io/tiny-harness/a2a/ext/task/v1`
**Media type:** `application/vnd.tiny-harness.task+json`

A2A's `Task` has an id, a context, a status, artifacts and history. A tiny-harness task
also has a name, a type, a goal, a description, acceptance criteria, participants with
roles, a parent and sub-tasks, and a plan of steps. They live in `Task.metadata` under
the key `io.github.madarauchiha-314.tiny-harness/task`, as the object below. The A2A task
state in `Task.status.state` stays the authoritative state.

Participants carry a role (`assignee`, `reporter`, `watcher`, `admin`); a message names
its sender in `Message.metadata.participant_id`, and a message from a non-participant is
refused with a status update whose message says why. A help request from the agent
travels as the `TaskStatus.message` of the `INPUT_REQUIRED` update.

## Intrinsic tools

The agent manipulates the extension through intrinsic tools, whose input schemas are
committed beside this page: `create_plan`, `complete_step`, `spawn_subtask`,
`ask_participant`, `create_task_for_participant`, `set_participant_role`, `list_skills`,
`load_skill`.
